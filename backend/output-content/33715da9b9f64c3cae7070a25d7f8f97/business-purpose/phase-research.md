## Phase Summary: Business Purpose & Domain Intent

**Product/Domain Purpose.** Next.js Commerce is a high-performance, server-rendered e-commerce storefront template built on the Next.js App Router. Its stated purpose is to provide a production-ready, SEO-friendly storefront that can be deployed to Vercel with minimal configuration. The template is explicitly designed as a starting point for commerce implementations, with a documented strategy of maintaining a Shopify reference implementation while enabling other providers to fork and swap the `lib/shopify` layer.

**Likely Users.** The primary end users are shoppers who browse products, filter and search collections, view product details, and manage a shopping cart. The secondary users are developers and merchants who clone or fork the repository to bootstrap a custom storefront, configure Shopify credentials, and deploy to Vercel. The README's deployment button and environment variable configuration (`SITE_NAME`, `SHOPIFY_STORE_DOMAIN`, `SHOPIFY_STOREFRONT_ACCESS_TOKEN`, `SHOPIFY_REVALIDATION_SECRET`) confirm a developer-first onboarding flow targeting Vercel hosting.

**Value Delivered.** The template delivers a complete storefront experience—home page with carousel and product grid, faceted search with collection filters and sorting, product detail pages with variant selection and image galleries, cart management with optimistic updates and modal display, and static content pages. It emphasizes performance through React Server Components, Suspense, and `next/cache`, and SEO through automatic metadata generation, OpenGraph images, a static sitemap, and `robots.txt`. The architecture separates client-side UI state (cart context) from server-side data fetching (Shopify GraphQL), enabling fast initial renders and efficient cache revalidation via `app/api/revalidate/route.ts`.

**Major Capabilities.** The system supports the full shopper journey: browsing (`app/page.tsx`, `components/grid/three-items.tsx`), searching and filtering (`app/search/page.tsx`, `components/layout/search/filter/index.tsx`), viewing product details (`app/product/[handle]/page.tsx`, `components/product/gallery.tsx`, `components/product/variant-selector.tsx`), and managing the cart (`components/cart/cart-context.tsx`, `components/cart/modal.tsx`, `components/cart/actions.ts`). Cart operations—create, add, remove, update—are performed via GraphQL mutations in `lib/shopify/mutations/cart.ts` and synced through server actions in `components/cart/actions.ts`. Content pages are fetched via `lib/shopify/queries/page.ts` and rendered with prose components. Navigation menus and footer links are driven by `lib/shopify/queries/menu.ts`.

**System Boundaries.** The boundary is clearly drawn between client-side React components (`components/`) and server-side Shopify integration (`lib/shopify/`). The cart state is managed locally via React Context (`CartProvider` in `components/cart/cart-context.tsx`), while product data, collections, and pages are fetched server-side through `lib/shopify/index.ts` (functions: `getProduct`, `getCollection`, `getCollections`, `getMenu`, `getPage`, `getPages`, `getProducts`, `getCart`, `createCart`, `addToCart`, `removeFromCart`, `updateCart`, `revalidate`). The revalidation API (`app/api/revalidate/route.ts`) sits at the edge of the Next.js runtime, exposing a mutation endpoint for cache invalidation after data changes. Checkout is explicitly external—`redirectToCheckout` in `components/cart/actions.ts` suggests the cart modal triggers an external Shopify checkout flow rather than handling payment within the repo.

**Key Uncertainties.** The README mentions alternative providers (BigCommerce, Ecwid, Geins) but the repository contains only Shopify-specific code, leaving the actual abstraction mechanism for provider swapping unspecified. The `test` script only runs `prettier:check`, indicating no automated unit or integration tests are configured. The exact GraphQL schema version and endpoint URL (`SHOPIFY_GRAPHQL_API_ENDPOINT` from `lib/constants.ts`) are not detailed in the supplied intelligence. The relationship between this v2 codebase (App Router) and the v1 reference is noted but not clarified.
