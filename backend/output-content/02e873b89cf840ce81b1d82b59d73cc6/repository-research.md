# Repository Research Brief

Research schema: 3
Phase: repository-wide

> This is an upstream reasoning artifact. It is not authoritative evidence or final SDLC documentation. Material claims must be verified against repository source.
This repository is Vercel’s actively maintained Shopify version of the Next.js Commerce starter template—a high-performance, server-rendered ecommerce storefront built on the Next.js App Router. The codebase is overwhelmingly TypeScript/TSX (roughly 65 files) and targets React 19, Next.js 15.6 canary, and Tailwind CSS 4, indicating a modern, cutting-edge React stack optimized for Vercel deployment. The README explicitly frames this as a reference implementation; Vercel plans to maintain only the Shopify variant, while alternative providers are expected to fork the template and replace the `lib/shopify` layer.

The product domain is headless ecommerce: the application consumes Shopify as its commerce backend via the Storefront API, using environment variables such as `SHOPIFY_STORE_DOMAIN`, `SHOPIFY_STOREFRONT_ACCESS_TOKEN`, and `SHOPIFY_REVALIDATION_SECRET`. Primary actors are anonymous shoppers browsing the storefront; there is no evidence of a custom admin panel, user accounts, or authentication beyond the storefront access token. The system boundary separates the Next.js frontend from Shopify’s backend, with external integrations limited to Shopify’s GraphQL API, Vercel deployment infrastructure, and optional revalidation via a secret webhook.

Major capabilities visible in the supplied evidence include: a homepage with a carousel and promotional three-item grid; a product detail page at `app/product/[handle]/page.tsx` with a gallery, variant selector, price, description, and add-to-cart flow; a search and category browsing experience under `app/search/` with collection filtering; a cart modal supporting optimistic updates; and marketing infrastructure such as dynamic opengraph images, sitemap generation, and robots.txt. The navbar provides mobile menu support and search access, while the footer renders dynamic menu items from Shopify. The search page at `app/search/page.tsx` and category page at `app/search/[collection]/page.tsx` both generate metadata and render product grids.

Representative workflows include adding an item to cart: the UI triggers a server action defined in `components/cart/actions.ts`, which calls `lib/shopify/index.ts` functions such as `addToCart` or `createCart`. The cart state is managed through a React context (`components/cart/cart-context.tsx`) using a reducer pattern with actions for updating items and totals, and components like `components/cart/add-to-cart.tsx` and `components/cart/edit-item-quantity-button.tsx` consume this context with `useOptimistic` for immediate feedback. Revalidation is handled by `app/api/revalidate/route.ts`, which exports a POST handler likely triggered by Shopify webhooks. The layout in `app/layout.tsx` wraps the application in `CartProvider`, includes the `Navbar`, and renders a welcome toast.

Key entities and state are defined in `lib/shopify/types.ts`, including `Cart`, `CartItem`, `CartProduct`, `Product`, `ProductVariant`, `Collection`, `Image`, `Menu`, `Page`, `Money`, and SEO types. The GraphQL layer is organized into fragments (cart, product, image, seo) and separated queries/mutations for cart, collection, menu, page, and product operations. `lib/shopify/index.ts` re-exports `shopifyFetch` plus catalog functions such as `getProduct`, `getProducts`, `getCollection`, `getCollections`, `getMenu`, `getPage`, and `getPages`, centralizing API communication. Local dependency edges show that cart mutations depend on cart fragments, product queries depend on product fragments, and collection queries depend on both product and seo fragments.

Implementation characteristics strongly favor server-side rendering and React Server Components. Cart actions are server functions, and the UI is composed from reusable primitives: `components/grid/index.tsx` provides `Grid` and `GridItem`, `components/grid/three-items.tsx` provides `ThreeItemGrid`, and `components/grid/tile.tsx` provides `GridTileImage`. The project uses `clsx` for conditional class names, `@headlessui/react` for accessible UI primitives, `@heroicons/react` for icons, and `sonner` for toast notifications. Styling is entirely Tailwind CSS v4 with PostCSS, and Prettier with the Tailwind plugin is configured for formatting.

Notable gaps and ambiguities include the absence of any test framework: the test script in `package.json` runs only `prettier:check`, meaning there are no automated unit or integration tests. The search functionality’s exact behavior—whether full-text product search or collection-only filtering—is not fully clarified by the file names alone. Additionally, while `app/api/revalidate/route.ts` exists, the intelligence does not detail the security model or payload validation beyond the `SHOPIFY_REVALIDATION_SECRET`. The template also assumes Shopify’s storefront API is sufficient for all catalog operations; complex checkout or payment flows delegate entirely to Shopify.

In summary, this is a reference Shopify storefront implementation emphasizing performance, modern React patterns, and Vercel deployment, with cart and catalog logic tightly coupled to Shopify’s Storefront API and a UI layer built from reusable, server-component-first primitives.
