# Repository Summary: Next.js Commerce (Shopify Edition)

This repository implements **Next.js Commerce**, a high-performance, server-rendered ecommerce application built on the Next.js App Router. It serves as the reference Shopify template from the Vercel commerce repository, designed to demonstrate modern web patterns including React Server Components, Server Actions, Suspense, and `useOptimistic` updates. The codebase is architected as a forkable template; alternative commerce providers can swap the `lib/shopify` implementation while retaining the surrounding UI and infrastructure largely unchanged.

The product domain is clearly ecommerce, with a focus on headless Shopify integration. The system exposes a complete storefront experience: product browsing and detail pages, collection/ category views, a search interface, shopping cart management, and checkout flow. All pages are generated using the App Router paradigm, with a mix of server-rendered and client-interactive components.

**Business and domain concepts** are strongly supported by the structure. The storefront is backed by Shopify’s GraphQL Admin API, accessed through a dedicated `lib/shopify` module that encapsulates fetches, mutations, queries, and fragments. Core domain entities include `Product`, `ProductVariant`, `ProductOption`, `Collection`, `Image`, `Cart`, `CartItem`, `CartProduct`, `Page`, `Menu`, `Money`, and `SEO` metadata. Relationships are explicit: a `Collection` contains products, a `Product` has multiple variants and options, a `Cart` aggregates `CartItem`s each referencing a `CartProduct`, and `Menu` items navigate between site sections. Filtering and sorting are modeled via `SortFilterItem`, `defaultSort`, `TAGS`, `HIDDEN_PRODUCT_TAG`, and `DEFAULT_OPTION` constants defined in `lib/constants.ts`. The cart state is managed centrally through a `CartProvider` and `useCart` hook, with Server Actions in `components/cart/actions.ts` mutating cart state and revalidating data via the `app/api/revalidate/route.ts` endpoint.

**Users and system boundaries** are delineated by the technology stack and integrations. The primary actor is the shopper interacting with a responsive, mobile-first storefront. The administrative or developer boundary is represented by the environment variables `SHOPIFY_STORE_DOMAIN`, `SHOPIFY_STOREFRONT_ACCESS_TOKEN`, and `SHOPIFY_REVALIDATION_SECRET`, which configure the Shopify connection and revalidation behavior. The system boundary encompasses the Next.js App Router (v15 canary), React 19, and Tailwind CSS v4, with user-facing UI built from HeadlessUI, Heroicons, and custom components. Server Components handle data fetching and rendering, while Client Components manage interactive behavior such as cart additions, variant selection, and search.

**Major capabilities and workflows** are evident across the page and component hierarchy. Product discovery flows through a grid layout (`components/grid`), category browsing via collections (`app/search/[collection]/page.tsx`), and targeted search (`app/search/page.tsx`). Product detail pages (`app/product/[handle]/page.tsx`) compose a gallery, variant selector, and description area, with add-to-cart actions flowing through `components/cart/add-to-cart.tsx` into the cart context and ultimately the cart modal (`components/cart/modal.tsx`). The cart supports item addition, removal, and quantity updates, with a “checkout” button that redirects. Revalidation is triggered via the `POST` endpoint at `app/api/revalidate/route.ts`, which imports `lib/shopify` and `next/server` to purge or refresh data—likely used after content or pricing changes in the connected Shopify admin. Sitemap generation (`app/sitemap.ts`) and robots (`app/robots.ts`) support SEO, while each page exports `generateMetadata` or static `metadata` to produce OpenGraph and Twitter card images via dedicated `opengraph-image` components.

**Important entities, state, and relationships** are organized through TypeScript types and GraphQL fragments. The `lib/shopify/types.ts` defines comprehensive types including `Cart`, `CartProduct`, `CartItem`, `Collection`, `Image`, `Menu`, `Money`, `Product`, `ProductOption`, `ProductVariant`, and `SEO`. Fragments in `lib/shopify/fragments/` encapsulate reusable query pieces for cart, image, product, and SEO, reducing duplication across queries in `lib/shopify/queries/`. The constants file exports `TAGS`, `HIDDEN_PRODUCT_TAG`, and `DEFAULT_OPTION`, suggesting a tag-based product organization system and default variant handling. The cart context maintains reducers and totals, while mutations (`lib/shopify/mutations/cart.ts`) map to Server Actions that modify cart state and invoke revalidation.

**External systems and integrations** center on Shopify as the backend commerce platform. The `lib/shopify/index.ts` exports a `shopifyFetch` utility and functions such as `getProducts`, `getProduct`, `getCollection`, `getCollectionProducts`, `getMenu`, `getPage`, and `getPages`, all of which communicate with Shopify’s Storefront API. The revalidation route ties into Shopify’s webhook or secret mechanism via `SHOPIFY_REVALIDATION_SECRET`. The template also references Vercel for deployment, with a “Deploy with Vercel” badge in the README and environment variables `VERCEL_PROJECT_PRODUCTION_URL` and `SITE_NAME` indicating first-class Vercel integration. UI dependencies include `@headlessui/react`, `@heroicons/react`, and `sonner` for toast notifications, while `geist` provides the custom font `sans` used in `app/layout.tsx`.

**Implementation characteristics** relevant across the SDLC are predominantly TypeScript-end throughout, with strict typing on props, contexts, and GraphQL shapes. Next.js 15’s App Router is the foundational framework, enabling Server Components by default and opt-in Client Components via `"use client"` directives (implicit in the JSX extensions). Tailwind CSS v4 powers styling, with container queries, typography, and postcss plugins configured in `postcss.config.mjs`. The build pipeline consists of `next build` and `next start`, with `pnpm prettier:check` enforcing code style. The repository’s architecture is deliberately modular: swapping the `lib/shopify` implementation is documented as the primary path for alternative providers, meaning the rest of the codebase—pages, components, and API routes—remains agnostic to the underlying commerce platform.

The codebase is oriented toward developer experience, deployment on Vercel, and operational concerns such as revalidation and environment‑driven configuration.
