# Phase Research Brief

Research schema: 3
Phase: business-purpose

> This is an upstream reasoning artifact. It is not authoritative evidence or final SDLC documentation. Material claims must be verified against repository source.
The repository implements Next.js Commerce v2, a high-performance, server-rendered ecommerce storefront built on Next.js 15 App Router. Its explicit purpose is to serve as a reference template for Shopify-powered storefronts, with a design goal of being forkable and adaptable to alternative commerce providers by swapping the `lib/shopify` implementation (README.md). The core business domain covers the typical retail customer journey: product discovery through collections and categories, browsing grid and list interfaces, search and filtering by tags and price ranges, cart management with quantity adjustments and checkout, and SEO-optimized page rendering.

Primary external actors are shoppers interacting with the storefront and an administrative system integrating with Shopify for product data and orders. The system boundary is the Next.js App Router layer, which renders React Server Components on the server and hydrates client-side interactivity where needed. The `lib/shopify` module encapsulates the backend commerce API, configured via environment variables `SHOPIFY_STORE_DOMAIN` and `SHOPIFY_STOREFRONT_ACCESS_TOKEN` (lib/shopify/index.ts). Navigation, product display, cart management, and search layers maintain clear import boundaries (e.g., components/layout/navbar/index.tsx importing mobile-menu and search components).

Key capabilities evidenced in the repository include product browsing and discovery via grid components and collection pages; search and filtering with UI components that query Shopify GraphQL operations; cart management via a React context with server actions for creation, item updates, and checkout redirection; and SEO/metadata generation per page type using fragment-sewed SEO data. A revalidation endpoint (`app/api/revalidate/route.ts`) supports incremental site regeneration triggered by backend changes. The filter system in `lib/constants.ts` defines sort and tag constants that shape product display, though the business rules for constants like `HIDDEN_PRODUCT_TAG` are not documented.

The technology stack is entirely TypeScript, including type guards that narrow Shopify error types. Styling is provided by Tailwind CSS v4 with a utility-first approach. UI primitives use @headlessui/react and @heroicons/react, with sonner for notifications and the Geist font utility. The repository is positioned as the Shopify reference template in the Next.js Commerce ecosystem, with Vercel as the recommended deployment platform and environment variables named accordingly.

Important uncertainties include the exact Shopify API version and GraphQL query depth, the full checkout flow beyond the `redirectToCheckout` server action, and test coverage or CI pipeline configuration. The business rules implied by filter constants and the precise interfaces required for alternative provider forks are also not fully enumerated, though the repository's design intent strongly suggests a modular `lib/shopify` swap pattern.
