# Repository Research Brief

Research schema: 3
Phase: repository-wide

> This is an upstream reasoning artifact. It is not authoritative evidence or final SDLC documentation. Material claims must be verified against repository source.
ReverseEngineer-SDLC is a web application designed to automate the generation of Software Development Life Cycle (SDLC) documentation for existing software repositories. Its core purpose is to analyze a target repository and reconstruct comprehensive documentation across standard SDLC phases: business-purpose, features, requirements, technology-architecture, high-level-design, low-level-design, implementation-detail, testing-harness, and future-directions. The application distinguishes itself by focusing on structured SDLC phase outputs rather than generic code summarization, requiring conclusions to be grounded in concrete repository evidence with clear delineation between verified facts, reasonable inferences, and unknowns.

Built as a full-stack application, ReverseEngineer-SDLC employs a Next.js frontend with React and TypeScript, and a Python backend utilizing FastAPI and Uvicorn. The frontend provides a user interface for initiating analyses and viewing results, while the backend orchestrates the analysis workflow, manages AI agents, and serves API endpoints for health checks, analysis triggering, and result downloads. Key technologies include the OpenAI Agents SDK for AI-powered phase analysis, Mermaid for diagram generation, and Pydantic for data validation. The application supports extensibility through modular agent and skill directories, each corresponding to an SDLC phase.

The system operates by accepting a repository input (via URL or local path), cloning it if necessary, and deploying specialized AI agents to analyze the repository for each requested SDLC phase. Each agent processes repository intelligence—gathered through file structure analysis, dependency mapping, and symbol extraction—to produce phase-specific documentation in Markdown format. The backend enforces a strict output contract: each phase must return a valid JSON object containing exactly two fields, `phase` (matching the canonical SDLC phase identifier) and `documentation` (the complete Markdown content). This structured output enables downstream consumption and packaging into downloadable ZIP archives containing all phase documents.

Primary users include software developers, architects, technical writers, and project managers needing to understand, document, or onboard to existing codebases. The tool serves as an automated analyst, reducing manual effort in reverse engineering SDLC artifacts. System boundaries encompass the input repository, the analysis engine (backend services and AI agents), and the output documentation package. External integrations rely on OpenAI's API (via the Agents SDK) for language model interactions, with experimental support for OpenRouter to test non-Anthropic models. Environment variables configure API keys (OPENROUTER_API_KEY, OPENAI_AGENT_TEST_REQUESTS, etc.), backend URLs, caching behavior, and Shopify store credentials—though Shopify integration appears limited to experimental or demo contexts rather than core functionality.

Notable implementation characteristics include a layered architecture separating concerns: repository intelligence collection, phase-specific agent execution, rendering, exporting, and diagnostics. The backend uses asynchronous processing for concurrent agent operations and includes resource monitoring to track CPU, memory, and process usage during analysis. Frontend components leverage React Markdown and Remark-GFM for rendering documentation, with demo capabilities showcasing sample outputs. The application incorporates testing harnesses for validating agent outputs and system behavior, alongside experiments investigating agent SDK process lifecycles and concurrent agent patterns.

Evidence from the repository indicates successful application to various codebases, as seen in the `backend/output-content` directory containing generated documentation sets for multiple work IDs. However, the intelligence does not reveal the specific prompts or internal logic used by agents during analysis, leaving ambiguities about how repository facts are transformed into phase documentation. Contradictions are absent, but gaps exist in understanding error handling for malformed repositories, scalability limits for monolithic codebases, and the exact mechanisms ensuring agent outputs adhere to the mandated JSON contract. The presence of experimental directories (`experiments/claude_sdk_process_test`, `experiments/openai_sdk_process_test`) suggests ongoing research into agent reliability, though these do not appear integrated into the main analysis flow. Overall, ReverseEngineer-SDLC presents a coherent, evidence-based approach to automated SDLC documentation generation, leveraging AI agents within a well-defined architectural framework.
