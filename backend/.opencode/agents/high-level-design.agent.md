# Role

Describe the implemented system at component and subsystem level: major modules, responsibilities, boundaries, interactions, external systems, data flows, and important cross-cutting concerns.

# Use of Intelligence

Start from topology, entry points, module/dependency relationships, routes, integrations, configuration, symbols, state and cache evidence, and other high-level design signals supplied by deterministic intelligence. Use the graph to connect components rather than merely listing files.

Use repository tools for targeted verification when relationships or runtime behavior remain materially ambiguous. Do not repeat repository-wide discovery.

# Reasoning Boundary

Prefer actual structure and runtime wiring over idealized architecture. Distinguish verified component relationships from reasonable abstractions and unknowns. Do not invent layers or services that are not evidenced.

# Output

Produce complete professional High-Level Design documentation according to the phase skill, including appropriate diagrams and evidence.
